# Bug Assessment: Missing TabViewItem Selection Highlight (`ShellTabBackgroundCanvas` / `InnerTabBackgroundCanvas`)

- **Slug**: shell-tab-background-canvas-highlight
- **Created**: 2026-10-23
- **Source**: pasted text and user UI screenshot
- **Verdict**: valid
- **Severity**: medium

## Report (verbatim or summarized)

The user reported an issue where the tab selection highlight capsule (`ShellTabBackgroundCanvas` / `ShellTabCapsule`) fails to render after closing all open dynamic tabs and reopening a new tab:

> "sửa lỗi tab ShellTabBackgroundCanvas  
> thao tác: mở app -> mở tab cơ sở dữ liệu -> về home và mở thêm tab cơ sở dữ liệu hoặc cài đặt, sau đó đóng hết tất cả cửa sổ từ bên phải, tiếp theo là tạo tab mới (có thể là settings hoặc databases) thì lỗi sẽ xuất hiện.  
> lỗi: không có hiệu ứng tô sáng cho TabViewItem  
> vấn đề có thể xảy ra ở cả DatabasePage và ShellWindow"

An accompanying screenshot (`media_1792773038195_0fbe5525.png`) showed the Home view after dynamic tabs were closed with the Home tab missing its selection highlight capsule.

## Symptom

When opening tabs, switching back to the anchored header tab (Home tab in `ShellWindow` or Connection tab in `DatabasePage`), closing all open dynamic tabs from right to left, and subsequently opening a new tab (Database, Settings, or Table tab), the newly selected tab completely lacks the Fluent selection card highlight capsule. The selected `TabViewItem` appears transparent and bare against the title bar / workspace background.

## Reproduction

1. Launch DataSphere on real desktop (`WinSta0\default`).
2. Open Database tab from Home card (`_tabService.OpenTab(DatabasePage)`).
3. Return to Home tab by clicking the anchored Home icon in `TabStripHeader`.
4. Open Settings tab from Home card (`_tabService.OpenTab(SettingsPage)`). The tab strip now contains `[Home] [Database] [Settings]`.
5. Close all dynamic tabs from right to left:
   - Click close (X) on Settings tab. Selection shifts to Database tab.
   - Click close (X) on Database tab. All dynamic tabs are closed; selection returns to Home tab.
6. Open a new tab (e.g. click "Cơ sở dữ liệu" or "Cài đặt" on HomePage).
7. Observe the tab strip: The new `TabViewItem` is selected, but has NO background capsule highlight (`ShellTabCapsule` in `ShellTabBackgroundCanvas` is completely missing).

## Suspected Code Paths

- `DataSphere/Controls/SlidingTabIndicatorBehavior.cs:486-515` — `UpdateVisualsPosition()` uses a fixed 4-retry cap with `DispatcherQueuePriority.Low`. When `TabItemsSource` transitions from 0 items to 1 item while `SelectedItem` changes simultaneously, the container `TabViewItem` is either not yet generated by `TabViewListView`, not yet loaded (`!selectedTab.IsLoaded`), or has `ActualWidth <= 0`. When the retry attempts expire, the visual placement is permanently abandoned.
- `DataSphere/Controls/SlidingTabIndicatorBehavior.cs:441-484` — `FindActiveTabViewItem()` and `FindSelectedTabViewItemInTree()` fallback mechanisms. During the transition when the container is not ready, `FindSelectedTabViewItemInTree()` searches the visual tree, which can cause race conditions or misidentify anchored tabs.
- `DataSphere/Controls/SlidingTabIndicatorBehavior.cs:532-537` — `targetBgWidth` calculation `Math.Max(0, (float)selectedTab.ActualWidth - 4.0f)`. If evaluated while `ActualWidth` is in an intermediate state (e.g., during tab open transition), `Width` and `Height` are set to `0`, collapsing the capsule border.
- `DataSphere/Views/Windows/ShellWindow.xaml.cs:98-106` & `DataSphere/Views/Pages/DatabaseGroup/DatabasePage.xaml.cs:28-36` — The mutual exclusion synchronization between `IsHomeSelected` / `IsConnectionSelected` and `TabView.SelectedItem = null` fires additional `SelectionChanged` events during collection changes that trigger premature indicator position calculations.

## Root Cause Hypothesis

**Confidence: High**

When all dynamic tabs are closed, `ShellTabView.TabItemsSource` (or `InnerTabView.TabItemsSource`) becomes empty, and selection falls back to the anchored header tab (`HomeTabItem` / `ConnectionTabItem`). At this moment, `ShellTabCapsule` is positioned at the anchored tab.

When a new tab is created via `Tabs.Add(newTab)` followed immediately by `SelectedTab = newTab`:
1. `Tabs.Add(newTab)` triggers `TabItemsChanged`, which invokes `UpdateVisualsPosition()` while `SelectedItem` is still null, keeping the capsule at Home.
2. `SelectedTab = newTab` changes `IsHomeSelected = false` and updates `ShellTabView.SelectedItem = newTab`.
3. `ShellTabView.SelectionChanged` fires immediately before WinUI 3's internal `TabViewListView` has generated, attached, and measured the container `TabViewItem` for the new item.
4. `FindActiveTabViewItem()` cannot find the container (`ContainerFromItem` is null, `ContainerFromIndex` is null, `HomeTabItem.IsSelected` is now false).
5. `UpdateVisualsPosition()` attempts up to 4 retries via `DispatcherQueue.TryEnqueue(DispatcherQueuePriority.Low)`. Because container realization, template application, and layout measurement during page instantiation exceed these low-priority retries or evaluate while `ActualWidth <= 4.0f`, `bgCapsule.Width` and `Height` are set to `0` or the retry loop aborts without applying visual coordinates.
6. Crucially, `SlidingTabIndicatorBehavior` does not subscribe to the newly realized container's `Loaded` or `SizeChanged` events, leaving the capsule permanently unrendered until another tab selection change occurs.

The identical pattern occurs in `DatabasePage` with `InnerTabView`, `InnerTabCapsule`, and `ConnectionTabItem`.

## Proposed Remediation

**Preferred**:
1. In `SlidingTabIndicatorBehavior.cs`:
   - In `FindActiveTabViewItem()`, when `tabView.SelectedItem != null` but `ContainerFromItem` is null or `!selectedTab.IsLoaded || selectedTab.ActualWidth <= 0`, hook into the container's `Loaded` and `SizeChanged` events as soon as the container is realized (or attach a one-time layout listener) to guarantee an update occurs when the container layout finishes, rather than relying solely on a fixed retry count.
   - When `bgCapsule` geometry is calculated, ensure that if `selectedTab.ActualWidth <= 4.0f` while `selectedTab` is selected, the behavior does not collapse `bgCapsule` to 0 width permanently; instead, retain visibility and update when `SizeChanged` fires.
   - When all dynamic tabs are closed and reopened, ensure seamless transition between the anchored header tab and dynamic items without orphan composition animations.
2. Verify both `ShellWindow` (`ShellTabBackgroundCanvas`) and `DatabasePage` (`InnerTabBackgroundCanvas`) maintain full visual indicator continuity.

**Alternatives**:
- Expose an explicit event or signal from `ShellViewModel` / `DatabaseViewModel` when a tab is added to force indicator layout pass. Trade-off: Violates UI-agnostic MVVM separation and leaks UI layout concerns into ViewModels.

**Files likely to change**:
- `DataSphere/Controls/SlidingTabIndicatorBehavior.cs`
- `DataSphere/Controls/TabMotionConfiguration.cs` (if retry or timing thresholds need tuning)
- `DataSphere/Views/Windows/ShellWindow.xaml.cs` (only if event hook synchronization is required, keeping 0 visual tree manipulation)
- `DataSphere/Views/Pages/DatabaseGroup/DatabasePage.xaml.cs` (symmetrical synchronization check)

**Tests to add or update**:
- Extend `scripts/reproduce-tab-highlight-bug.ps1` into a regression verification test (`scripts/verify-tab-highlight-fix.ps1`) verifying that the selection capsule background color (`252, 251, 251`) is present across all steps: initial launch, tab open, switch home, tab open, close all, reopen.

## Risks & Considerations

- **Clean MVVM Compliance (Principle I)**: All changes must remain purely inside `SlidingTabIndicatorBehavior` (attached behavior) and declarative XAML bindings. No visual tree manipulation (`Children.Add`, manual `Visibility` overrides) in `ShellWindow.xaml.cs` or `DatabasePage.xaml.cs`.
- **Performance & Smooth 60 FPS (Principle IV)**: Subscribing to container events (`SizeChanged`, `Loaded`) must be properly cleaned up / detached to prevent event handler leaks when tabs are closed.
- **Dark/Light Theme Contrast**: The capsule background brush must dynamically adapt to theme changes.
